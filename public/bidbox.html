THE IMMUTABLE IRON RULE • NON-NEGOTIABLE

Your agent prepares the file, it NEVER awards the tender. Procurement law across all 54 African states strictly mandates that final awards rest solely with a statutory human tender committee. Every finding your agent generates must rigorously cite the source document, page, and release hash. An unsourced flag against a supplier is worse than no flag at all.

Precise Terminology

Jargon Defined Up Front

Strict definitions enforced throughout the technical review. Misrepresenting these boundaries in your submission will penalize your architectural score.

hub MCP (Model Context Protocol)

An open specification developed to expose structured client-side and server-side tools, resources, and evaluation prompts to foundation models without brittle custom APIs.

smart_toy Agentic AI (Not a Chatbot)

A software system that formulates a dynamic multi-step plan, calls deterministic external tools, analyzes execution feedback, checks its own work, and handles edge failures autonomously.

data_object OCDS Standard

Open Contracting Data Standard: the global open JSON schema used by 9 African sovereign procurement portals covering planning, tenders, awards, contracts, and implementation.

receipt_long Tender vs. Bid

A tender is the public institution's solicitation of goods or civil works. A bid is an individual supplier's submitted commercial and technical proposition.

lock_open Open-Weights Models

Downloadable foundation model weights (Qwen 2.5, Llama 3, Gemma, Mistral, Aya) deployable on sovereign African cloud or on-prem servers to maintain complete citizen data privacy.

front_hand Human-in-the-Loop Gate

A non-bypassable programmatic pause where the autonomous agent halts before consequential milestones, presenting structured evidentiary diffs for human sign-off.

Engineering Blueprint

Hard Requirements & Submission Criteria

Strict technical constraints to guarantee authentic, Sovereign African agentic software rather than superficial chatbot wrappers.

RULE 01 • CUSTOM MCP SERVER

3+ Sovereign Tools

Write your own MCP server exposing at least 3 tools. Crucially, at least one tool must draft, file, or flag. Read-only query endpoints are not an agent's hands.

RULE 02 • THIRD-PARTY MCP

External Server Justification

Integrate at least one MCP server you did not write (e.g. SQLite, GitHub, Filesystem, Brave Search, PostgreSQL) with explicit written rationale for why it is essential.

RULE 03 • FRAMEWORK CHOICE

Open-Source Orchestration

Build using recognized open-source orchestration libraries: LangGraph, CrewAI, Pydantic AI, smolagents, or clean Python/TypeScript native loops.

RULE 04 • DATA SOVEREIGNTY

Open-Weights Execution

The entire end-to-end evaluation must execute cleanly against an open-weights foundation model (e.g., Qwen 2.5, Llama 3, Mistral, Gemma, Aya) to guarantee local data residency.

RULE 05 • DEFENSIVE TELEMETRY

Structured Logging & Human Gate

Every tool call must output exact timestamps, raw tool arguments, and returned schemas. Execution must pause at consequential thresholds for named human signoff.

RULE 06 • NEW WORK CLAUSE

Fresh 5-Day Sprint Code

All submitted code must be built within the official challenge period. Pre-existing proprietary agency software will be detected via Git commit verification.

IMPORTANT GUIDANCE FOR HACKERS: HISTORICAL RELEASES VS. SYNTHETIC BIDS

Public OCDS portals legally publish tenders, awards, and contracts, but rarely publish raw un-awarded supplier bids (due to commercial trade secret protections). For your evaluation agent, we recommend pairing real historical tender requirements from PPRA or BPP with either: (a) synthetic test bidder submissions generated with LLMs, or (b) sanitized historical bid PDFs provided in the Bid Box Starter Repo.
