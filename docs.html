CHAPTER 01 · ORIENTATION

What Quorum is

An agentic review desk for public procurement. The agent reads the file, checks it against the rules and the law, and drafts findings with citations — then stops at a gate and waits for named humans to decide.

Quorum prepares the file. It never awards the tender. Everything on this platform is built around that single line: the agent may read, extract, check and draft, but the decision to award or return belongs to the committee — signed under a real name and recorded permanently.

THE STANDING RULE

QUORUM PREPARES THE FILE. IT NEVER AWARDS THE TENDER. THE COMMITTEE SIGNS — THE AGENT NEVER DOES.

The platform has three faces on one address. The landing page explains the product. The sign-in screen authenticates officials. The workspace behind #/dashboard is where the work happens: evaluations, findings, approvals, the supplier list, and these documents.

THE MISSION IN FOUR MOVES

MOVEWHEREWHAT HAPPENS

ReviewAgent runsThe agent reads the pack, extracts requirements and sweeps the rules. Findings appear with page-level citations.
DecideApprovalsThe gate. A committee member reads the cited findings and signs to award, or returns the tender for clarification.
RecordAward historyThe history appends the decision, the signer and the time. Nothing is edited; entries are only added.

YOUR FIRST FIVE MINUTES

  1. 1Open the workspace from the top of the page once signed in.
  2. 2Read the Overview's four live counters — runs in progress, issues found, sourced coverage and approvals waiting.
  3. 3Open Suppliers from the sidebar and check the register of bidders your entity deals with.
  4. 4Launch a run against one tender — or a sample pack — and watch the register fill in.
  5. 5When a gate appears, read the findings, then sign or return. That is the whole loop.

CHAPTER 02 · THE ENGINE ROOM

How a review runs

A run is one tender reviewed end to end by the quorum-mcp agent — a LangGraph pipeline calling five MCP tools, with every call logged.

THE LIFECYCLE OF A RUN

  1. 1Stage the pack. The tender's documents are placed in its folder; every file is listed.
  2. 2Extract requirements. The SHALL/must clauses of the notices are pinned — read-only, nothing stored.
  3. 3Sweep the rules. Bids are parsed, prices compared, identifiers validated and notices checked — each finding is born with a citation.
  4. 4Draft the redline. For a finding, the agent drafts the correction, using the configured LLM or the template fallback.
  5. 5Raise the gate. The award submission bundle is filed as pending: execution is blocked until a named human approves.
  6. 6Decide. Approve executes the filing and closes the run; return re-opens the loop for clarification.

THE FIVE TOOLS

TOOLKINDWHAT IT DOES
tender_documents_listREADLists the tender's files for a reference via the official filesystem MCP server.
extract_requirementsREADPins the SHALL/must clauses in a tender's notices. Read-only — it stores nothing.
draft_redlineWRITESDrafts a redline for a finding, using the configured LLM or the template fallback.
flag_findingWRITESFlags a finding. Accepted only if its citation names a document in the tender and its anchor text appears there.
file_gate_submissionIRREVERSIBLEFiles the award submission bundle. Execution is blocked until a named human approves at the gate.

THE IRREVERSIBLE TOOL

file_gate_submission is the only irreversible call in the stack, and it is deliberately powerless on its own: it files a pending bundle and returns gate_pending. Nothing executes until a person with a name signs.

Every call — read or write — lands in the audit log with actor, inputs, outputs and duration. The Tools & models screen renders that same log; the raw record lives at mini-services/quorum-mcp/data/tool-log.jsonl on the host.

CITATION DISCIPLINE

A finding whose citation does not name a real document in the tender is rejected before it ever reaches the committee. If you remember one engineering rule: nothing uncited survives the pipeline.

CHAPTER 03 · DAILY WORK

Launching an evaluation

The New evaluation wizard takes three steps and never starts until you confirm the scope. Most runs take minutes to brief.

THE WIZARD, STEP BY STEP

  1. 1Details. Enter the tender reference and the published title exactly as they appear, then choose the source format: OCDS records, a PDF pack or the email bag. The wizard suggests the next reference in your register's sequence, or reads one out of a staged filename.
  2. 2Documents. Drop up to twelve files. Each moves from RECEIVED to PARSING to INDEXED; nothing can launch while a document is still being read. Uploads mirror to cloud storage when configured, or stay in the local vault.
  3. 3Scope. Choose which checks run — specifications, quantities and prices. Page-level citations stay on for every finding, always.
  4. 4Launch. The run is queued and you land on Agent runs, where it goes live in front of you.

STAGING STATES

STATEMEANING
RECEIVEDThe file is in hand and queued for reading.
PARSINGThe reader is extracting text, tables and price lines.
INDEXEDThe document is readable by the review and will be cited.

A sample registry ships with the stack — real packs with notices, bids and OCDS records. Staging a sample is the fastest way to see a full review without touching a live file; the run behaves exactly like a real one.

NAMING MATTERS

The reference you type is the join key for everything afterwards: files, findings, gates and history rows. If the published document names the tender differently, keep the document's spelling — the agent matches on what the papers say.

CHAPTER 04 · THE EVIDENCE

Findings & the rulebook

Every issue is a finding: a rule, an item, the evidence, and a citation to the exact page, line or clause where it was seen.

Findings are grouped into seven classes so a committee can scan a file quickly: DOCUMENT, COMPLIANCE, REGISTRY, PRICING, ARITHMETIC, DISCLOSURE and LOGISTICS. A finding with no citation is marked unsourced and should not be relied on — treat it as a question, not a conclusion.

THE RULE REGISTER

RULESEVERITYWHAT IT CATCHESTHE COMMITTEE'S MOVE
R-DOC-MISSINGMEDIUMA document the notice lists as REQUIRED that a bid never references.Ask the bidder to supply it, or mark the bid non-responsive.
R-SUPPLIER-IDHIGHA supplier identifier that breaks its own national scheme — or a line that states none at all.Verify the identifier against the registry before relying on the bid.
R-BUYER-MISSINGMEDIUMA tender notice that never names the buyer.Trace the buyer to the record; a notice nobody owns is a governance gap.
R-AWARD-OVER-BUDGETHIGHAn OCDS award value above the published tender value.Review the justification before any award moves.
R-PRICE-OUTLIERHIGHA unit price two times or more against the peer median on the same line item.Check the arithmetic and the specification; outliers concentrate abuse.
R-SPEC-DEVIATIONHIGHBid lines offering alternatives, requesting deviations or stating non-compliance.Weigh the deviation against the specification before scoring.
R-VALUE-OUTLIERHIGHA bid value more than twice the median of its peers.Confirm the scope is comparable before treating the bid as competitive.
R-OVER-BUDGETHIGHA bid value above the budget ceiling parsed from the notice — including currency mismatches.A bid above the ceiling cannot be awarded without a lawful revision of the budget.

HOW A FINDING LIVES AND DIES

  1. 1OPEN — raised by the agent, waiting for the committee's attention.
  2. 2CLEARED — the gate signed to award; the finding is part of the record that informed the decision.
  3. 3RE-CHECK — the tender was returned for clarification and the agent re-verifies.

READING A CITATION

Citations name the file and the anchor — a page, a clause, a price schedule. Open the cited document at that anchor. If the anchor doesn't exist, the finding doesn't pass the pipeline in the first place.

CHAPTER 05 · THE HUMAN GATE

Approvals, the committee and the gavel

The gate is the handover moment: the agent's work stops, and named humans decide.

A pending gate shows the supplier, the value and how many findings were flagged. Read them against the cited documents, then sign to award or return for clarification. A return is not a rejection of the agent — it re-opens the file so the questions you raise can be cleared.

THE TWO DECISIONS

DECISIONWHAT IT RECORDSWHAT FOLLOWS
APPROVEThe award, signed by the officer who decided.The filing executes and the history appends AWARDED with the signer and time.
REJECT / RETURNA return for clarification, with the signer recorded.The loop re-opens; findings become RE-CHECK while the agent re-verifies.

Signatures are enforced by the agent service, not in the browser. An approval is refused unless the approver is a present member of the committee roster or the signed-in officer; if the roster cannot be read at all, the decision is refused rather than guessed. Nobody can approve into a name that isn't theirs.

SUMMONING A SITTING

  1. 1Open Committee from the sidebar to see the roster in roll-call order: the chair, the members, the excused, and you.
  2. 2Summon a sitting to call the roll — it timestamps the summons and refreshes the count.
  3. 3Quorum is checked before decisions: the default standing house is nine seats with five required.
  4. 4When quorum is present, any pending gate can be decided.

THE GAVEL PROTOCOL

THE AGENT QUEUES THE FILE AT THE GATE. THE COMMITTEE READS THE CITED FLAGS. AWARD OR RETURN — BY NAMED HUMANS. THE LEDGER LOGS IT, PERMANENTLY.

CHAPTER 06 · THE LAW

Zambia's procurement regime

First up among the jurisdictions the platform serves: Zambia — the Public Procurement Act No. 8 of 2023, which repealed and replaced the 2008 Act, and the Public-Private Partnership Act No. 14 of 2009.

The engine reviews a file with the lawful methods in view: open and limited bidding, direct bidding, simplified bidding, force account, community participation, purchases from other procuring entities, PPP concessions, and the alternative-method route via the Zambia Public Procurement Authority. The method register below is the engine's own data — loaded live, so what you read here is what the review applies.

READING A METHOD CARD

FIELDWHAT IT MEANS FOR THE FILE
Legal basisThe statute the method rides on — name it in the record when the method is questioned.
When this is lawfulThe conditions that must hold. A choice that doesn't fit them is a finding waiting to happen.
Value bandWhere the law draws a line — simplified bidding up to K1 million, open bidding above it.
AdvertisingWhether the invitation must be gazetted and advertised, or goes only to nominated firms.
Float periodThe minimum time bidders get: four weeks national, six weeks international.
Award authorisationWho signs: the Procurement Committee, the Central Tender Committee, or the Authority — never the agent.

DEVIATIONS NEED A GROUND

Every non-open method must trace to a named statutory ground in the record. Urgency without a stated cause is the classic red flag — the review is built to catch exactly that.

ALTERNATIVE METHODS

A method outside the list needs the ZPPA's approval before use, not after. For the agent, an unapproved method is a STOP: the review still runs, but the gate must name the missing approval.

The register underneath all of this is the supplier roll: the certificates and registrations a bidder must hold. Keep it current — the review reads it, and so does the committee.

CHAPTER 07 · THE REGISTER

The supplier list

Every bidder the platform knows, held in the agent’s store with the registration detail Zambia's regime asks a bidder to carry.

The register is the platform's single source of truth for who the bidders are. It is what the review leans on when it validates supplier identifiers, and what a committee opens when a name at the gate needs checking. It is maintained by officers and written through the same audited path as everything else — additions, edits, suspensions and removals are all tool calls in the log.

WHAT EACH FIELD IS FOR

FIELDWHY IT IS COLLECTED
Supplier nameThe name that appears on bids — keep the legal spelling on the certificate.
Registration numberThe PACRA / Registrar of Societies number that identifies the legal entity. Picking a firm off the ZPPA roll fills it as published.
ZRA Tax PINThe Zambia Revenue Authority taxpayer number.
ZRA Tax Clearance NoThe certificate number a compliant bid must carry.
Tax clearance expiryThe certificate's standing. An expired clearance makes a bid non-responsive — the classic check a committee runs first.
Sector regulator + numberNCC, NHCC, ERB, ZPPA and similar registrations where the category requires one.
CategoriesWhat the firm supplies or the works it executes — the basis for matching a supplier to a tender.
Contact detailsWho signs for the firm, and how to reach them when a bid needs clarification.

KEEPING THE REGISTER TRUE

  1. 1Add a firm: open Suppliers and press REGISTER A SUPPLIER — the intake opens as a dialog over the register. Name and registration number are the only required fields; everything else hardens the record.
  2. 2Edit: open the row and update as papers renew — every change stamps the update time and lands in the audit log.
  3. 3Suspend or blacklist: a firm that should not be considered while a question is open, or at all.
  4. 4Remove: for entries created in error. The audit log still remembers — removal is a recorded act, not an erasure.

The intake opens with the published record at hand. The agent service ships the ZPPA roll — a derived reading of Zambia's e-GP open contracting data, the Zambia Public Procurement Authority's record published through the Open Contracting Partnership. Pick a firm off the roll and the form fills itself: legal name, PACRA number, address, telephone and the supply categories its award history points to — every value exactly as published, and every field still the officer's to correct. The record suggests; the officer confirms.

THE ROLL'S SOURCE

Zambia Public Procurement Authority — e-GP record, released through the Open Contracting Partnership (data.open-contracting.org/en/publication/3, CC BY 4.0). The roll ranks firms by awards on the record; tender and award counts and value totals are computed over it. The register stays the platform's own truth — the roll is only a head start.

STATUSES

STATUSMEANING
ACTIVEConsiderable in reviews and at gates.
SUSPENDEDHeld back pending resolution of a question — visible but flagged.
BLACKLISTEDExcluded. The strongest statement the register can make.

SUPPLIER IDENTIFIERS

The R-SUPPLIER-ID rule reads what bids state about themselves: an identifier line that breaks its own national scheme — or states none at all — is flagged HIGH. A truthful register is what lets the committee tell a typo from a fabrication.

CHAPTER 09 · STANDARDS

Evidence & data sources

A finding is only as lawful as its source. Every bid is read against national portals, supplier registries and the OCDS record — and each finding cites which.

The platform reads structured and unstructured materials alike: OCDS 1.1 releases, PDF packs, the email bag and staged markdown. Four standards hold across all of them: OCDS 1.1 for publication records, the MCP tool layer for filesystem and extraction access, LLM drafting for redlines, and page citations for every finding.

WORKING WITH SOURCES

  1. 1See the registries an officer can check against: the Data sources screen reads the OCP Data Registry and lists every African dataset it publishes — country, publisher, coverage span, update frequency, formats and latest retrieval, each dated.
  2. 2Expand a country to inspect a dataset before leaning on it: licence, published counts, OCID prefix, and links back to the registry page, the publishing policy and the publisher's own portal.
  3. 3Connect the portals: for every dataset the agent opens the published file, reads the first OCDS release and keeps its OCID as proof, then checks the publisher's own portal. Every check is dated and saved — a portal that fails is shown failed.
  4. 4A dataset the publisher stopped updating carries the registry's own flag — findings that needed it are gaps in the file, never a silent pass.
  5. 5Request a source when a registry or portal is missing. It is logged, and its absence is visible rather than silent.

The register is read as published: coverage dates, retrieval dates, formats, file sizes, licences and counts are the registry's own figures, and the screen names the retrieval date of the snapshot it draws. Where a publisher states no licence, the registry shows an em dash — and so does the screen. Beside it sits the connection record: the first OCDS release the agent read from the published file, and the last answer from the publisher's own portal — both dated, both checkable again.

Every portal can be switched off, one dataset or a whole country at a time. A portal that is off is not silently dropped: its row dims, names who set it and when, the connection pass skips it, the header counts what is switched off, and the transition is written to the audit trail. Turning it back on puts it straight back into the pass.

READING A RECORD

Citations point at anchors — a page, a clause, a schedule line. When you dispute a finding, quote its anchor back at the record; the pipeline either places the text there or the finding never existed.

CHAPTER 10 · ACCOUNTABILITY

The audit trail

Who did what, when, and against which record — permanently, in three places that outlive any browser session.

THE THREE RECORDS

RECORDCONTAINSWHERE
Audit logEvery tool call: actor, inputs, outputs, status, duration.The Live activity feed and Tools & models render it; the raw file lives at mini-services/quorum-mcp/data/tool-log.jsonl.
Award historyEvery AWARDED and RETURNED decision with the signer and time.Award history in the sidebar.

Rows in the award history are appended, never edited. The same is true of the audit log: entries only accumulate. If you need to answer an audit question — who approved this, on what evidence, in what order — the answer is assembled from these three records and nothing else.

PRACTICE

Before a sitting, open Live activity and let it run during the meeting. The sequence the committee reads is the sequence the record will keep.

ONE NAME, ONE SIGNATURE

Decisions are recorded under the officer's name. Do not share a sign-in: the record will read it as one person deciding everything.

QUESTIONS OFFICERS ASK

CAN QUORUM AWARD THE TENDER?
No — by design. It prepares the file and stops at the gate. The committee signs.
WHAT IF THE AGENT SERVICE IS OFFLINE?
Reads that depend on it pause, and approvals cannot be recorded until it is back. The interface shows AGENT · OFFLINE rather than pretending.
A FINDING IS WRONG. WHAT NOW?
Quote its citation back at the record. Findings that can't be anchored to a document never pass the pipeline; for the rest, the committee's return is the correction mechanism.
WHERE DOES MY DATA LIVE?
On your host: the agent service's data directory for evaluations, gates, suppliers and logs; the local vault or cloud storage for documents, as configured.
WHICH JURISDICTIONS ARE SUPPORTED?
The method register opens with Zambia — Public Procurement Act No. 8 of 2023 — and grows by jurisdiction; the engine validates only the identifier schemes it actually knows.
